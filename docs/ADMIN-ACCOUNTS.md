# 账号管理与部门移除

创建用户的初始密码预填为 Qcode@2026，可修改；新建账号和密码输入框分别使用 autocomplete=off 和 new-password，减少浏览器把当前管理员凭据填入新用户表单。浏览器密码管理器仍由用户控制。

存在启用套餐时，创建普通用户须先选择套餐，再选择其中已启用的默认对话模型；后端同样校验模型归属。没有启用套餐时保留个人额度创建方式。管理员可重置密码，用户可在桌面端账号菜单修改密码；两种操作都会撤销该账号所有设备的登录。桌面入口需要重新构建安装包。

## v4 数据库升级至 v5

运行时、前端和业务接口不再包含部门。所有启用的共享 Skill 和知识库均对用户开放。新数据库直接使用 v5；已有 v4 数据库必须明确执行一次离线迁移，不在启动过程中自动兼容旧格式。

先通过已审核的部署流程获取代码并正常停止网关，再在数据库目录可访问且配置了 DB_PATH、KEY_ENCRYPTION_SECRET 的环境中执行：

- 预览：node scripts/remove-departments.js
- 应用：node scripts/remove-departments.js --apply

脚本先生成服务器本地加密 v4 备份，然后在同一个 SQLite 事务中移除部门表、索引及用户、Skill、历史请求的关联字段，升级到 v5。用户、套餐、订阅、Key、模型、技能、知识库、反馈和请求用量记录保留；原先继承的个人额度、默认模型和 Key 固化到账号上。部门共享总额度约束移除。进行中的请求、错误密钥、已存在的备份目标或非 v4 数据库均阻止写入。

迁移备份需配合迁移前的 v4 代码恢复；当前常规备份与恢复只接受 v5，不增加运行时旧格式兼容。确认迁移完成后再启动新服务。回滚时先停止新服务，用旧版维护工具将加密 v4 备份恢复到新数据库路径，再切回旧代码与数据。历史一次性迁移脚本中出现的旧字段仅用于处理其对应版本，不是现用业务入口。
