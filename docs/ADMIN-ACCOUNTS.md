# 账号管理与部门移除

创建用户的初始密码预填为 Qcode@2026，可修改；新建账号和密码输入框分别使用 autocomplete=off 和 new-password，减少浏览器把当前管理员凭据填入新用户表单。浏览器密码管理器仍由用户控制。

创建用户仅填写账号、初始密码、套餐和登录设备上限，须先创建并启用套餐。额度由套餐配置，用户表单不提供个人额度。模型由用户在客户端自行选择。后台仅支持重置普通用户密码；管理员和演示账号由系统配置，角色固定，不支持后台重置密码、停用或删除。普通用户可在桌面端账号菜单修改自己的密码，修改后撤销所有设备登录。用户页仅保留刷新与创建入口，不提供 CSV 导入、下载模板及批量创建用户接口。

## v4 数据库升级至 v5

运行时、前端和业务接口不再包含部门。所有启用的共享 Skill 和知识库均对用户开放。新数据库直接使用 v6；已有 v4 数据库先按本节升至 v5，再按 [套餐精简](SIMPLIFY-PLANS.md) 升至 v6。

先通过已审核的部署流程获取代码并正常停止网关，再在数据库目录可访问且配置了 DB_PATH、KEY_ENCRYPTION_SECRET 的环境中执行：

- 预览：node scripts/remove-departments.js
- 应用：node scripts/remove-departments.js --apply

脚本先生成服务器本地加密 v4 备份，然后在同一个 SQLite 事务中移除部门表、索引及用户、Skill、历史请求的关联字段，升级到 v5。用户、套餐、订阅、Key、模型、技能、知识库、反馈和请求用量记录保留；原先继承的个人额度、默认模型和 Key 固化到账号上。部门共享总额度约束移除。进行中的请求、错误密钥、已存在的备份目标或非 v4 数据库均阻止写入。

迁移备份需配合迁移前的 v4 代码恢复；当前常规备份与恢复只接受 v6，不增加运行时旧格式兼容。完成 v5 → v6 迁移后再启动新服务。回滚时先停止新服务，用旧版维护工具将加密 v4 备份恢复到新数据库路径，再切回旧代码与数据。历史一次性迁移脚本中出现的旧字段仅用于处理其对应版本，不是现用业务入口。
