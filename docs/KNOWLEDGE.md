# 企业知识库、个人资料与记忆

管理员批量上传企业资料后，页面显示上传及整理进度、文件数量和当前文件；按实际完成文件数更新进度，单份模型执行时显示等待动画。整理结束后自动展示左侧目录树、右侧内容，逐篇查看是可选步骤。需要调整时点击“编辑”，修改标题、摘要或正文后点“确定”，最后通过顶部“一键发布”统一生效。替换、撤回、重试和删除收在“更多操作”中。个人资料在客户端“资料库 → 个人知识库”批量上传，服务器仅负责临时解析，客户端下载保存后在本机查看和编辑。管理端不展示个人正文，聊天附件不会自动加入知识库。

## 文件与处理

- 支持 UTF-8 TXT、Markdown、文字型 PDF、DOCX、XLSX；企业100份，个人本机10份，每个账号服务器同时最多10份临时处理任务。不设置每份文件大小的业务额度。知识上传入口先鉴权，按Node可用堆内存的1/32设置单次传输预算，同时最多接收2个上传请求；超出资源预算提示拆分，不影响其他业务接口原有传输限制。
- 解析在受限工作线程执行，单次60秒、256 MB堆限制；Office解压内容最多32 MB，PDF最多200页，Excel最多20000个非空单元格，正文最多20万字符。
- PDF保留页码；DOCX保留提取文本行位置；Excel保留工作表、单元格地址与行范围，后续片段读取时包含首段表头。公式只读缓存结果，不执行或重算。
- 扫描页、嵌入图片不自动识图；无文本PDF页面明确报错，需要先识别或移除空白页。混合图文Office文件当前只提取文字和表格。
- 优先按标题、段落拆分，目标每节点约1500字符、约2000字符时按段落分组；表格和紧随的备注、适用条件尽量成组。不能安全拆分的长段落可保留，超过12000字符时要求先调整原文件。单篇最多400节点。
- 模型摘要最多100字符，不凑长度。能力配置中设置知识整理渠道和模型；已存在启用的千问官方渠道时，默认使用 `qwen3.8-max`。切换只影响后续处理，不自动重做已发布资料。
- 入库调用沿用渠道Key池，记录实际Token用量并检查用户额度；上游未返回用量时记录未知，不估算扣费。

企业处理状态为等待、处理中、就绪、失败；失败可手动重试。服务器重启后继续待处理任务。替换原文生成新版本，已发布版本继续使用到管理员发布新版本；企业原文件和版本保存在服务端，不整体同步到员工电脑。

## 本机个人资料

客户端提供“个人记忆”“个人知识库”两个Tab，企业资料单独折叠展示。记忆直接按文章阅读；知识库左侧有展开箭头、文件夹和章节层级，选择目录后右侧显示Markdown文章。编辑统一在文章右上角，替换与删除在“更多操作”中。仅展示已保存份数，上传处提示最多10份，不使用进度式的“2/10”文案。新用户记忆为空，不预填偏好或语言设置。

个人批量上传后自动解析、下载，不需要管理员审核或发布。下载包含原文件、目录元数据和章节正文，校验文件摘要和版本后先写入独立版本目录，再原子更新本地目录入口；全部落盘并读回核对后，才发送下载确认清理服务器处理记录。下载或本地写入失败时不确认，确认时断网会保留本地副本并重试清理；客户端重启后继续记录中的任务，不接管其他电脑的处理任务。

本机按网关、账号及账号创建时间隔离。每篇资料有原文件、目录JSON和章节Markdown；界面默认左侧目录、右侧阅读，编辑后仅保存本地。点击“打开本地文件夹”可用外部编辑器修改章节或memory.md；读取使用当前文件内容，保存时核对内容revision，防止覆盖其他会话或外部编辑器改动。资料ID和目录受控，拒绝路径穿越与符号链接。换电脑需自行备份并迁移个人目录，没有自动云同步。

断网后已保存资料仍可查看、编辑和通过本地工具读取；新上传整理和模型请求需要网络。上传内容会发送给整理模型，对话使用的相关正文仍会发送给所选模型，本机保存不等于内容从不离开电脑。

## 企业资料增量整理

上传支持一次选择多份文件，逐份提交并排队解析；某份失败不影响其他文件。同名同内容的当前资料会跳过重复处理。需要替换已有资料时使用该资料的“替换文件”，避免仅凭标题误覆盖。

每份企业资料生成章节与摘要后，将新资料正文和现有已发布目录交给整理模型；模型通过受控动作展开目录、读取相关旧节点，再提交新增或修改建议，最多6轮、20项。没有旧资料时不增加这次模型调用。个人资料不进行跨文档自动修改。

建议仅存为草稿，左侧“有更新”中可查看修改原因和前后正文，也可编辑建议或忽略单项建议。模型不能直接操作服务器文件、删除节点或大规模重排目录。未发布草稿可通过“重新整理”重新生成建议；手动编辑不调用模型。若修正新资料正文，确认后移除依赖该章节生成的关联建议，避免建议与依据不一致。

界面仅保留一个“一键发布”，在所有整理任务结束后可用，编辑时需先确定或取消。一键发布需确认，并在一个SQLite事务中发布全部就绪资料及其关联章节；失败文件不包含在内，确认时明确提示。关联资料的已发布版本必须仍与模型读取时一致，且不能存在其他未发布版本；同一批草稿不能同时修改同一旧节点。有冲突时整批不发布，核对“有更新”并忽略重复建议，或对版本过期的草稿重新整理后再发布。

更新后的章节保留旧依据和本次新依据的文件ID、版本、节点和位置，原始上传文件不被改写。关联资料产生新版本，旧节点ID失效。撤回或删除依据文件后，依赖该文件的生成章节不再参与检索；恢复发布该依据可恢复检索，重复发布不会重复执行旧建议。已进入聊天上下文的内容无法追溯撤回。

## 对话与Skill

一个 `qcode-knowledge` Skill说明知识库与记忆的使用规则，普通共享Skill继续按原流程同步。该名称由内置技能保留，后台创建和编辑普通技能时不能使用。

每个共享 Skill 最多包含256个文件（含 `SKILL.md`），序列化文件清单上限8 MB。管理端创建和编辑技能的上传入口先校验管理员身份，再接收最多10 MB的JSON请求，其他普通业务入口仍为4 MB。后台和客户端须同时更新；旧客户端升级前不要发布超限技能包。知识正文通过三个账号绑定的MCP工具读取：

- `knowledge_catalogue`：分别返回企业和本机个人目录，可按scope或local:目录ID继续导航；小目录完整返回，超过目录预算后按文档和章节分层，并提供分页游标。
- `knowledge_read`：每次读取1～6节点及父级原文，正文最多24000字符，返回文件、版本和位置。
- `memory`：仅在本机记忆开关开启时读取或按用户明确要求更新记忆，写入必须携带当前revision。

MCP通过本机带随机鉴权的回环桥接访问网关，不向模型提供供应商Key或网关登录令牌。OpenCode 1和2共用受管理的MCP配置。模型自行决定是否检索，用户不必选知识库；通常2～4轮，但实际调用次数由Agent与证据充分程度决定，服务端不保证固定轮数。目录预算采用序列化大小控制，不把字数当成精确Token。

服务端每次列企业目录、读取节点、下载个人处理结果和确认清理都检查权限。本地个人节点使用local:前缀，不转发到服务器。企业资料撤回、删除或发布新版后，旧节点不能继续读取；已进入聊天上下文的内容不能追溯清除。

## 个人记忆

每人一份本地 `memory.md`，默认关闭，开启时创建，最多2000字符。客户端默认只读，需要时编辑、确定或清空；不保存整段对话。用户明确要求记住、纠正或删除时，Agent先读后合并；revision防止多个会话及外部文件修改相互覆盖。常见密码、Key形式被写入校验拒绝。模型请求由本机桥接读取当前记忆，仅在开启时提供参考；服务器没有云端记忆接口。关闭后停止注入和工具更新，已有文件保留。

资料归属根据账号ID、名称和创建时间绑定，业务数据库恢复后新建账号即使复用数值ID，也不会继承旧处理任务或本地资料。服务器账号删除不远程删除用户电脑文件。

## 存储、发布与备份

新增 `data/knowledge-tree.sqlite`，保存企业资料与个人临时处理任务，与业务数据库同目录，使用WAL；保留原有独立向量存储代码。业务数据库结构版本仍为v6，不自动清空旧数据。个人资料需通过当前客户端上传并下载到本机。

管理端与客户端需一起升级。现有业务加密备份不包含独立知识库文件；完整备份应停服后备份整个data目录，保留同一时点的数据库文件。不要把知识库、记忆、测试原文或数据库提交到Git。

新增依赖为 PDF.js（Apache-2.0）、Mammoth（BSD-2-Clause）、ExcelJS（MIT），版本锁定在server锁文件中，部署使用原有全量部署入口安装。

服务端入口：`knowledge-runtime.js`；解析：`knowledge-parser.js`；树与预算：`knowledge-tree.js`；持久化：`knowledge-tree-store.js`。专项测试为 `knowledge-runtime.test.js`，覆盖格式解析、发布、权限、版本、记忆与账号ID复用。实验评测结果单独见 `TREE-RAG-PROTOTYPE.md`，不作为正式检索质量保证。
