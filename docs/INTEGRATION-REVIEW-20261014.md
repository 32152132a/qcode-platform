## 临时目录问题

历史 C:/Users/庆/AppData/Local/Temp/qcode-install-* 是开发用真实安装回归夹具，两个目录合计约 1.5 GB，不是员工的正式安装位置。qcode-bootstrap-*、qcode-gateway-* 等也是测试夹具。正式安装曾有 qcode-setup-* 解压目录未清理的问题，每次约 96 MB；已修复成功和失败路径的 finally 清理，并增加验证。客户端更新 downloads 下本次 ZIP 与解压文件也改为结束后清理，成功和散列失败路径均验证通过。编译成功或失败时清理本次编译临时目录；超时且编译器仍运行时保留以免干扰进程。

真实 EXE 与升级测试成功后清理自身大文件夹具；本次开发测试 TEMP 指向项目 artifacts/test-temp，避免继续堆积系统 Temp。历史残余由另一个对话清理，本任务未批量删除历史目录。安装 logs、个人配置/历史/项目，以及当前与回滚版本属于有意保留的内容。

Windows 本机 Inno 资源写入偶发 EndUpdateResource 110；本次正式包和独立测试包均成功构建，未修改杀毒软件配置。该现象发生于开发机编译阶段。

## 实机追加修复

Windows PowerShell 将 File.Replace 第三个参数的 $null 转为无效空路径，导致已存在的加密登录文件再次写入失败。改用 [NullString]::Value 保持原子替换，新增真实 Windows DPAPI 连续覆盖三次、中文字段往返、无明文 Token 和无临时文件残留测试。此问题会影响桌面重复启动和 Token 刷新，因此修正版递增到 0.4.10。

0.4.10 正式 EXE 已在当前 Windows 账号覆盖安装，版本指针和系统注册项验证通过；真实桌面启动、浏览器登录页和密码显示切换均通过，安装后系统 Temp 没有新增 qcode-setup-*。验收截图保存在忽略目录 artifacts/actual-0.4.10-browser-login.png。线上健康和新前端资源验证通过；额外管理员登录受到现有设备会话上限限制，未撤销用户现有会话，已登录管理员可刷新页面使用。
