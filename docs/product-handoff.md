# QCode 0.3.0 交接与统一验收

## 本地已验证

28 项自动化测试通过：用户和权限、凭据轮换、并发配额、部门继承、流式用量、Key 加密、Skill 路径安全、撤销进行中请求、SQLite、加密备份与迁移、客户端桥接和更新版本比较。浏览器测试覆盖登录、部门/用户创建、启停、Key 检查、Skill 发布、系统设置、刷新恢复登录、11 个页面、移动端和退出。另已实测 Windows DPAPI 会话保存、自动续期和真实 Harness Web 启动（使用本地模拟模型）。

原有真实配置与旧数据没有覆盖。新安装默认 SQLite；旧 JSON 可保留，迁移需要停止服务。模拟模型和演示账号用于替代暂未提供的真实信息，不代表实际模型编程质量。

## 一次性验收顺序

1. 先运行演示，后台创建部门、员工、模型、Key，测试启停、密码重置、权限、配额耗尽和恢复。
2. 两台员工电脑安装，分别使用 Web/TUI，选择项目，确认文件生成、代码执行和会话继续；检查两账号配置及会话不混用。
3. 使用真实模型完成工具调用、长输出、流式 usage、断网、Key 失效和模型切换；核对供应商账单与平台统计差异。
4. 开着 Harness 撤销会话/禁用用户；等待访问 Token 过期后继续请求；重新登录和换电脑，验证登录数量限制。
5. 按部门发布/禁用 Skill，检查自动同步；发布更高客户端版本验证更新及回滚；检查最低版本拦截。
6. 在目标服务器验证 Docker、HTTPS、重启自启、内网访问、代理来源限制；用正式备份恢复到新数据库并重新登录。
7. 按实际团队规模压测并连续试用，确认响应时间、内存、数据库增长和备份耗时，再扩大使用范围。

## 仍需明确的边界

- 当前单网关进程，SQLite 使用进程独占，数据在内存中缓存；不是多节点/大规模集群方案。
- OpenAI Compatible 协议已实现，不代表 DeepSeek、Ollama、vLLM、LM Studio 的每个版本及模型组合都已实际验证。
- 未运行目标企业 Docker/HTTPS 环境，未完成多台员工电脑和长时间压力验收；Windows 安装器已在隔离目录完成 Node/Harness 实际联网下载安装和版本检查，企业策略仍需目标电脑验证。
- EXE 默认未签名。安装需要下载固定 Node/Harness，尚无完全离线运行环境包。
- Token 预留为保守估计，价格统计不等同供应商发票。配额为平台控制，不能替代供应商硬额度。
- 员工不获得供应商 Key；若内网模型服务允许匿名直连，必须由部署方限制其网络访问，客户端代码无法替代防火墙。
- 配置/会话目录隔离不限制 Harness 对当前 Windows 账号有权限的文件进行读写。需要强隔离时使用独立系统账号或容器。
- 备份和审计归档已有脚本，调度由运维配置；没有自动删除用量账本。备份必须单独保存加密密钥。

源代码上传与安装包构建属于交付；真实 Key、数据库、私人令牌和演示凭据不随 Git 上传。请以本说明的已验证范围为准，不将功能已实现等同于生产环境已验收。
