# 图片能力

在“模型与服务 → 配置图片能力”集中配置：生图站点、生图模型、默认识图模型。无需启用开关；生图站点和模型一起清空即停用，默认识图模型可单独清空。每人每日生图张数放在高级设置，默认 10。旧版 enabled 配置保留协议兼容，页面不展示开关。

生图复用已接入且启用的官网或中转站及其 Key，仅支持兼容 /images/generations 的 PNG Base64 返回。默认识图模型从已接入且可用的对话模型中选择，可来自本地部署、官网或中转站，管理员必须确认上游实际支持图片输入。这里只是服务分类，不会让纯文本小模型获得视觉能力。

员工不选择或配置图片模型。客户端保留正常对话模型切换，使用现有附件入口上传/粘贴图片，也可以在对话中要求生成图片。所有受管理的对话模型声明接收图片附件，网关将带 image_url 的整个请求交给默认识图模型；含历史图片的后续请求也沿用此路由，直到上下文不再包含图片。纯文字请求仍使用员工选择的对话模型。请求记录、配额、实际模型和 Key 均以网关实际调用为准，不把图片模型凭据交给客户端。没有配置或识图模型被停用/删除时返回 VISION_UNAVAILABLE，不误标记原对话模型下架。

附件沿用 OpenWork 压缩与本地工作区 .opencode/openwork/inbox/chat-attachments/<session>/ 保存流程，Base64 图片经网关转发；Responses 转换成 input_image。网关不把提示词或图片内容写入请求日志。仍沿用整个请求 4 MB（含历史）的大小限制与既有保守配额预留，正常返回时按上游 Token 用量记账，缺失用量不保证精确视觉计费。

普通对话模型下架时，保留原会话和文件，不自动换模型或重发；选择器显示“模型已下架，请重新选择”，目录加载中不以内部 ID 代替名称。员工可以在原会话选择其他可用模型继续工作。

本地模拟服务、类型检查及无头浏览器用于自动验收；真实识图和生图需后台部署、客户端重新打包安装并配置模型后再验收。当前不支持修改上一张生成图或视频生成。
