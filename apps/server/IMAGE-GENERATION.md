# 对话生图（第一版）

- 管理端“模型与服务 → 配置图片能力”：选择已有官网或中转服务、填写生图模型即可使用；一起清空站点与模型即可停用。每日张数放在高级设置，不自动产生收费验证请求。
- 服务需兼容 POST /v1/images/generations，并返回 data[0].b64_json 的 PNG；不支持仅返回图片 URL 的服务、图片编辑或视频。DeepSeek 聊天服务不因此具备生图能力。
- 员工保持当前聊天模型，说“帮我生成一张海报”。新内核工具 qcode_generate_image 调用现有 OpenWork 生图扩展，通过本地鉴权桥接转发到网关；用户不接触上游 Key。
- 生图模型不导入聊天模型列表。网关按管理员设置选择生图模型，忽略客户端提交的模型 ID，使用所选服务的 Key。
- 每次一张，成功和进行中的任务占用每日张数；失败释放张数。所有尝试仍计入既有日/月/总请求次数限制，共用账号并发；不虚构 Token 或费用。请求日志记录 purpose=image_generation、generated_images、状态及耗时，图片和提示词不存入网关数据库。
- PNG 保存在当前会话工作区 artifacts 目录，文件名带随机后缀。管理员清空生图配置、停用站点或 Key 后，新请求立即被拒绝。失败和超时不自动重发。
- 上线需部署 qcode-platform，并重新构建、安装 qcode-openwork 客户端；不需要重编译 qcode-opencode 内核。现有图片在关闭功能后仍保留。
- 已完成模拟上游测试；真实中转站是否支持对应生图模型、Key 是否有生图权限和额度，需要管理员配置后生成一张验收。
